# Windows 原界面保留与自动更新方案修订

状态：负责人已确认采用方案 B“参考项目完整实现与原字体”，进入实施。日期：2026-10-09。

## 问题背景与目标

负责人最新要求：所有 UI 和字体优先保留 Mac 原版；无法直接使用时，参照 https://github.com/IAmTheBlurr/CompositorWindows 。原先的 Avalonia 基础编辑器仅复用了布局尺寸，默认控件与原版明显不同，不能作为完整原界面交付。当前只有未合并的开发 PR，没有正式 Windows 发布；Mac 主分支未被改变。

Mac 原项目使用 SwiftUI/AppKit 与系统字体，不能直接在 Windows 上运行同一套原生控件。负责人指定的备选 Windows 工程使用 Qt 6.8.3、自绘深色控件、向量图标与仓库提供的 InterVariable.ttf，另有图层、蒙版、选择、绘画、滤镜等现有功能。参考 SHA：dfd0044d39b63ea49112a0e316a9460af29acdea。它的 Mac 基线是 1.0.4/a19db9011282399785dc18efcfded904627bdcc2，当前下载为 0.1.4 预览版，更新仍为手动，不承诺与最新 Mac 全功能一致。

目标：保留参考 Windows 项目的完整界面结构、控件绘制、图标和 Inter 字体，仅新增中文显示与自己的签名更新，并在 GitHub 自动跟踪、验收、构建和发布。最终软件与安装包放在负责人指定的 D:\Applications；应用目录单独使用 Compositor，不覆盖其他软件。

## 至少两个方案

| 方案 | UI 与字体 | 编辑能力 | 维护与代价 |
| --- | --- | --- | --- |
| A：继续 Avalonia 基础版，仿制参考外观 | 可以嵌入同一 Inter 字体，但须逐个重做所有控件和面板，难以保持整套界面一致 | 保持目前基础栅格子集，参考工程高级面板没有对应功能 | 将长期维护第二套 UI 和功能；与当前“所有 UI”要求不符，暂不推荐 |
| B：以参考 Windows Qt 工程为产品实现基线 | 保留 VisualStyle、EditorIcons、字体文件和各现有窗口/面板，避免重新设计外观 | 继承该工程已实现能力，保留其已知限制 | 需要接入 C++/Qt 构建依赖、中文显示和正式签名更新；推荐 |

推荐 B。保留原 Mac fork 与历史，在独立 Windows 产品分支引入参考项目并准确记录来源，保留全部原始版权、字体与依赖许可证。原先未发布的基础版分支留作恢复记录，不将其自制 UI 作为正式产品。

Jev 实际辅助判断：按本机技能使用进程中的 TYPESAFE_API_KEY 请求官方接口（指定 jev.ps1 在本机不存在）。返回模型 jev-1.13.0，选择 reference_qt，probability=1.0，confidence=1.0。它仅辅助判断方案与用户要求的匹配程度，不替代授权、编译、字体许可或验收证据；未保存/输出密钥。

## 接口与数据结构

1. 两个准确的源码基线：macUpstreamCommit 与 windowsUpstreamCommit；同步检查、候选提交与成功发布提交分别记录。参考 Windows 工程的源码更新可合并到 Windows 产品；Mac 新 Swift/Metal 能力只形成迁移待办，未经适配不得标为已实现。
2. 中文模块：新增 LocaleOptions（语言可选，缺省行为保持参考工程英文默认），仅翻译显示文字、菜单、状态、错误和可访问性名称。命令 ID、混合模式序列化值、文件格式字段与公开 C++ 方法签名不变。产品入口显式选择简体中文。
3. 字体：保持参考项目 InterVariable.ttf 字节与字体尺寸/权重策略。Inter 缺少的中文字形采用明确的中文回退字体；不把中文回退说成 Apple 原字体。所有已有控件、图标、面板样式和窗口外观偏好保留。
4. 正式更新：保留参考工程手动更新和测试信任接口的既有默认行为，新增正式频道与生产信任配置，不使用 TEST-ONLY 私钥或 --test-trust。生产元数据以本仓库公钥校验，绑定完整版本文件清单、字节数与 SHA-256；保留项目保存确认、健康检查、重启与失败恢复机制。
5. 发布记录包含产品版本、两个上游 SHA、候选 SHA、架构、完整资产清单、签名和健康检查结果。自动同步不得覆盖自有发布脚本、签名公钥或开发规则；冲突/失败保持旧版索引。

对参考工程现有入口或更新调用路径如确需改动，另在实施票据列明原因、受影响调用方和回滚方法，在本方案确认后才修改。优先新增入口/适配方法与可选配置，不改既有公开签名。

## 场景与可执行验收门

体验门先定义，再实现契约；新增中文/正式更新门先运行失败，再编码。

| 真实场景 | 体验门 | 确定性门 |
| --- | --- | --- |
| 用户看到完整原参考界面 | 同场景截图对照：工具栏、菜单、图层、变换、调整/滤镜/文字/选择/颜色面板与窗口偏好保持同一套控件 | 检查原 VisualStyle/EditorIcons/字体资源未被替换，字体文件哈希相同；执行对应原有 UI/编辑测试 |
| 用户使用中文 | 菜单、弹窗、错误、快捷键提示中文可读，中文不被截断；英文字符继续使用 Inter | 翻译覆盖清单完整；协议 ID 与序列化值不翻译；中文路径、名称、输入保存重开 |
| 作者/Windows 移植者有源码更新 | 维护者看到来源基线与是否已迁移，已有用户仍有可用版 | 两路同步无变化不重复发布；保护路径、冲突、格式变化阻断错误 stable 发布 |
| 首次安装及两次后续升级 | 自己的旧版启动可发现更新，保存后下载、安装、重启；三版中文项目保留 | GitHub 候选构建、签名、实际安装、健康检查；至少三个递增构建连续升级；坏签名/坏包不可安装 |
| 更新/保存失败 | 中文原因、可重试或继续旧版，未保存修改不得丢失 | 使用参考工程已有安装故障注入与恢复门，加生产信任门；核对旧版与项目完整性 |

参考工程原有完整回归曾为 926/932，六项历史失败已在 KNOWN-ISSUES 中公开。这些不是本任务通过证据，不得隐藏或把它们重写为通过。执行范围、外部样例缺失与新增回归必须明确记录。用户原有/参考工程正式 tests 与 fixtures 保留，不能按文件名删除；仅清理本任务生成的精确临时路径。

## 实现步骤

1. 讨论确认推荐方案 B；现有基础版 PR 保持草稿，不发布其 UI。
2. 在独立分支引入固定 SHA 的 Windows 参考源码，保留历史/归属/许可证与原 tests，不修改 Mac 原工程。准备场景与红门。
3. 接入现有完整 UI、Inter 字体与中文显示；复用原编辑路径和公开接口，运行原有针对性门及中文门。
4. 接入自己的生产签名更新与 GitHub 双基线同步、C++/Qt 自动构建打包。下载依赖按锁文件校验。若本机缺编译工具，先用 GitHub Windows runner 构建，下载到当前 Windows 实测；不擅自安装管理员级工具链。
5. 从 GitHub 正式资产执行三版升级、健康检查、中文项目保存与重开验收，通过后启用稳定频道。
6. 安装到 D:\Applications\Compositor，安装包放 D:\Applications，更新说明与真实验收记录；清理本任务临时验证产物。
